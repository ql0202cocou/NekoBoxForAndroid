# UI 截图基线

`app/src/test/java/io/nekohasekai/sagernet/uitest/` 里的 Robolectric 用例（SDK 35）把页面渲染成 PNG，
与本目录的基线逐像素比较。文件名由 `ScreenshotMatrix.kt` 的一张表生成：
`<画面>/<主题>-<亮暗>_w<宽度dp>_f<字号>.png`，画面与档位以那张表为准。

## 矩阵（139 张）

画面 25 个：配置页、配置页「已连接」、分组、路由、设置一级页、设置 7 个分类页、关于、工具的网络 / 备份、网络测试、日志、VMess / Shadowsocks 编辑器、
6 个对话框（删除确认、未保存提醒、主题选色、列表选择、文本输入、行内校验错误）。分层，每个轴的每个取值都覆盖到：

| 层 | 覆盖 | 档位 | 张数 |
| --- | --- | --- | --- |
| A 主题层 | 配置页、已连接、分组、路由、设置一级、关于、网络 / 备份、VMess 编辑器、主题选色 | 粉 / 灰 / 黑 × 亮 / 暗，411dp、字号 1.0 | 60 |
| B 布局层 | 除「行内校验错误」外的 24 个画面 | 粉亮，360dp、字号 1.3（最挤的一档） | 24 |
| C 补角 | 配置页、设置一级 | 粉亮，360dp / 1.0 与 411dp / 1.3 | 4 |
| D 默认层 | 不在 A 层的 15 个画面 | 粉亮，411dp / 1.0 | 15 |
| E 完整色板 | 配置页 | 其余 18 种主题 × 亮 / 暗，411dp / 1.0 | 36 |

- 分类页、备份页与编辑器截全长（把窗口根视图手动撑到内容刚好放下的高度再画，见 `UiViews.kt`）；其余按窗口大小。
- 使用 hdpi（411dp 宽约 617 px）渲染，控制基线体积。备份页按实际滚动内容高度截图，不把 ViewPager2 的内部列表算成正文。
- **每个档位一个独立的用例**（`ScreenshotTest` 参数化）：Robolectric 在同一个用例里换夜间模式 / 主题后，已缓存的
  颜色状态列表会沿用上一档的解析结果（实测：Tab 选中项文字在暗色下仍是亮色下的黑色），所以不能在一个用例里循环多个档位。
  新增档位时先看渲染结果是否与它在沙箱里第一个渲染时一致（见下面「审查流程」第 1 步）。

## 规则

- **只在录制平台比较**：macOS arm64。原生绘图的字体光栅与抗锯齿跨系统不保证一致，其它平台（含 release CI）
  只渲染、打印「跳过比较」，渲染崩溃照样失败；行为用例在所有平台都跑。
- **阈值 0 个像素**。同一平台两次渲染逐字节一致，没有理由放宽；以后要放宽，必须在本文件按 golden 基线
  `RELAXATIONS` 的格式写明原因，不能改代码里的阈值了事。
- **缺基线 = 失败**，绝不自动生成。本目录里有矩阵之外的文件（或矩阵里的文件缺失）= `ScreenshotManifestTest`
  失败，该测试是纯 JVM，所有平台都跑。唯一允许的非图片文件是本 README。
- 比较失败时，实际图与差异图（变化的像素标红）在 `app/build/outputs/screenshots/{actual,diff}/`。

## 重录只能显式点名

```bash
./gradlew app:testOssDebugUnitTest -Pscreenshots.record='^config-list/'
```

`-Pscreenshots.record=<正则>` 对基线相对路径做 find，只重写名字匹配的截图，其余照常比较；没有「默认全部重录」。
重录只在录制平台上生效，其它平台会报错。

## 审查流程

1. 跑测试，逐张看差异图，确认每处变化都是有意的；
2. 只按正则重录这些截图；
3. `git diff --stat` 应恰好是这些 PNG；
4. 与引起变化的代码放进同一个提交。

整体换肤同样逐张看，不许为了让测试变绿直接重录。

## 行为用例与已知缺口

同目录之外的 `uitest/*Test.kt` 还有不截图、所有平台都跑的行为用例：

- `ThemeIndicatorContrastTest`：21 种主题 × 亮色 / 夜间 / 纯黑夜间，在活动与对话框主题下检查实际节点标记、分组和规则文件更新进度与各自背景、轨道的对比度至少为 3∶1；顶部与连接按钮保留旧版配色。
- `MainPagesRecreateTest`：四个一级页面 × {重建、旋转}：页面类型、Dock 选中项、标题不变；配置页选中的分组不变；
  设置分类页重建 / 旋转后仍停在该页；分类页返回后一级页的滚动位置恢复。
- `CloseBeforeLoadTest`：一级页面与两个编辑器创建后立刻销毁、再放行后台，不得有未捕获异常（U4b「关闭后回调不碰 View」）。
- `EditorRecreateTest`：改字段后重建 / 旋转不丢；模拟进程重建（存实例状态 → 销毁 → 清空内存里的编辑缓存 → 新建）
  按 EditorSession 规则：缓存丢了就从实体重新初始化并重新认领，被别的编辑器接管就关闭。
- `EnterAnimationTest`：显式打开动画，检查冷启动入场动画（M5）。
- `PageSlideTest`：逐帧检查一级页面、全部七个设置分类的进入和返回，验证页面不透明、边缘相接、标题栏和设置列表完整显示；连续切换连同退出覆盖层检查不闪空，且只提交最后目标并保留首页滚动位置；覆盖 Dock 跨层切页、返回箭头 / 系统返回、RTL、关闭/减慢动画、取消排队、旋转和进程重建。
- `KnownUiGaps` / `KnownUiGapsTest`：**现在就不满足验收**的项的名单。每项写明出处（open-issues.md 的条目，或写明
  「Robolectric 实测发现」及其依据）和验收内容，探针场景在 `UiScenarios.kt`。`KnownUiGapsTest` 断言每一项**仍然不满足**：
  某一项修好了，它就失败并要求把条目删掉、把场景改挂到对应的 `*Test` 里成为普通用例——与 golden 基线
  `RELAXATIONS` 同理，名单上的放宽没用到也失败。不许为了让测试变绿而新增条目；U4d 结束时名单应为空或逐项写明理由。
- 场景的前置条件不成立（例如列表根本没滚动）一律抛错，不算「不满足」，免得已知缺口的探针空转。
- 旋转用 `configurationChange()` 之后要补一次 `visible()`（Robolectric 重建出来的 Activity 不会自己 attach 窗口）。

## 环境约定

en-US、时区 UTC、动画时长缩放 0、固定的夹具时间戳、文档保留地址（192.0.2.x、example.com）与虚构凭据；
截图密度 hdpi（411dp 宽约 617 px），其它行为用例沿用 xhdpi。设备与夹具见 `UiTestBase.kt`、`UiFixtures.kt`。

独立内容页的新增基线覆盖关于、工具的网络 / 备份、网络测试和日志。关于页的应用版本号固定为夹具值，核心版本由测试影子提供；真实的署名、许可和功能行仍按页面渲染。
